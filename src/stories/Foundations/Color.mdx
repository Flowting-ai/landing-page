# Color & Roles

The canvas is a **warm cream → espresso monochrome (~90%)**. Color is seasoning, never wallpaper.
Everything extends the vendored Kaya ramps — the marketing layer only assigns *roles*, it never
invents new hexes.

> **Why monochrome.** The product is intangible AI orchestration; the brand bet is to make it feel
> like a warm, *kept* object. A restrained warm-neutral field does the emotional work (paper, leather,
> developed film) and lets a single accent note land. A rainbow palette would read as generic SaaS —
> the one thing we're avoiding.

> **Why mauve, used this sparingly.** It's the *muted* purple from Kaya (the product deliberately
> dropped the saturated brand purple), so at a signature dose on a warm field it reads as a kept,
> personal note — not a tech-brand statement. Blanketing it everywhere would burn that. **One
> signature moment per page.**

## The CTA is not the accent

The primary call-to-action is the vendored **`@/components/kaya/Button`** (espresso/dark, embossed,
squircle). Mauve is for links and the signature visual — it never becomes the button. Keeping
interactive weight in the dark button and identity in the mauve note means neither competes.

## Hard rules

- **Colorblind (red–green):** meaning is **never** carried by color alone — pair shape + label +
  position. The accent is decorative/CTA, **never a status signal**. The focus ring is **ink**, not a color.
- **Tints reduce chroma, not opacity.** Lowering opacity greys a color out; pulling chroma keeps it
  alive. Build palettes/gradients in **OKLCH** so midpoints don't go muddy.
- **No coral.** The former `#E0613A` is fully removed; never reintroduce it.

## Theme toggle (mauve ⇄ ochre)

Use the toolbar **theme** switch. It flips `data-theme` on the real token layer
(`src/styles/tokens/marketing.css`), so the **ochre fallback** — the documented one-token accent swap
should brand ever object to mauve — previews live across every story. This is truthful: the same
switch would work on the site.
