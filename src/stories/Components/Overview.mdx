# Component Library

The marketing site is built on the **vendored KDS components** in `src/components/*` — the same atoms
the product ships. This library **documents** them (and the bespoke marketing organisms built from
them); it does not re-port or duplicate anything.

## Adapt, don't fork (the rule)

The vendored atom is the **single source of truth**. A "marketing version" means the atom **adapted
via tokens/props or a thin variant** — shared interaction/identity, marketing-tunable surface — like
the CTA Button (locked interaction, marketing sizing). It **never** means a duplicated component that
drifts. If an atom needs a genuine *structural* marketing adaptation, we flag it and decide
deliberately (see "Flagged" below) rather than copy-paste.

## Available, not yet surfaced (deferred)

Product-app plumbing not used by marketing — vendored and importable, but **no stories** until a
marketing visual needs one (avoids documenting surface we don't use):

`UsageBarChart` · `StreamingIndicator` · `ChatInput` · `Checkbox` · `InputField` ·
`Dropdown` / `DropdownMenuItem` / `DropdownSection` internals · `Popover` · `Switch` ·
`ModelSelectItem` (0 live uses) · `Sparkline` is queued only as a concept-visual ingredient.

## Flagged for deliberate adaptation

- **Button → marketing `lg` size:** a larger, more generous CTA size is wanted for marketing. Deferred
  — `kaya/*` is read-only; the right move is an **additive geometry-only size** upstreamed into KDS,
  not a fork. Pending sign-off (see Primitives → Button).

## Each story carries

Variants + states + a one-line **marketing-usage note**. Tokens only — no magic numbers. Product
surfaces (MessageBubble, StatCard) use the **inherited KDS type ramp**; marketing chrome uses the
marketing tier (see Foundations → Typography).
